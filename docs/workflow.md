# 工作流 · 一条片子的完整流程

> 一句话：**AI 管机械，人管内容；AI 出清单，人点头才剪；进了剪辑软件，AI 消失。**

---

## 五步

```
① 转录  →  ② 出清单  →  ③ 人确认  →  ④ 剪切  →  ⑤ 验证
   ↑                                      ↑
   AI 全自动                          必须人点头
```

---

### ① 转录（先提音量，再识别）

**第 0 步 · 提音量（必做）。**

绝大多数口播素材音量偏低（动圈麦、手机内置麦的先天问题）。低音量直接喂 ASR，同一段话能读出三种不同结果。

```bash
# 只重编码音频，视频流 copy —— 快一个数量级，时间轴与源片逐帧一致
ffmpeg -y -v error -i "原片.mp4" -af "volume=+18dB" -c:v copy -c:a aac -b:a 192k \
  "<work_dir>/原片_g18.mp4"
```

> 稳不稳的判断：`+18dB` 和 `+30dB` 各跑一版短样，**两次识别结果一致才算稳**。不一致就承认听不出，别硬猜。

```bash
bash scripts/transcribe.sh --srt "<work_dir>/原片_g18.mp4"
```

产出两个文件（与输入同目录同名）：

| 文件 | 粒度 | 用途 |
|---|---|---|
| `<名>.srt` | 短语级（2–4 秒一条） | 内部稿 |
| `<名>.words.json` | **逐字**（最细 80ms） | 定位剪点 |

---

### ② 出剪辑清单（不动手）

读 `words.json` + `srt`，按 `docs/rules.md` 的规则算剪点。

**输出格式**：

```
起始 → 结束 ｜ 内容 ｜ 原因
```

**只列，不剪。**

---

### ③ 人确认

把清单给人看。人会说：

- 「按这个剪」→ 进 ④
- 「第 3 条别剪」→ 改清单再确认
- 「这里删掉」→ **注意**：这可能是在说他自己在剪辑软件里删，不是让你删。**问清楚。**

> **判断信号**：要说删的那句，如果删掉之后意思会变——它是**内容**，不是剪点。

---

### ④ 剪切（确认后）

**音画一起剪**，同一个 `filter_complex` 里同步切同步拼：

```bash
# 每段 trim，然后 concat（注意 [vN][aN] 串后直接接 concat，中间不能加 ';'）
-filter_complex "[0:v]trim=start=A:end=B,setpts=PTS-STARTPTS[v0]; \
                 [0:a]atrim=start=A:end=B,asetpts=PTS-STARTPTS[a0]; \
                 ... ; \
                 [v0][a0][v1][a1]concat=n=N:v=1:a=1[outv][outa]" \
-map "[outv]" -map "[outa]" 输出.mp4
```

**输出新文件名**（`-cut-v2`、`-cut-v3`…）。**永不覆盖。**

---

### ⑤ 验证（必做）

**对成片重跑一遍识别**，与源稿逐段比对——确认没吞字。

- 只比时长**不够**。
- 哪处吞了半个字 → 单独回退那一处。
- 自己校验没过、还没交付的版本 → 删掉，别留两个版本。

---

## 产物放哪

**所有中间产物只落一个地方：`work_dir`（可清理区）。**

它的标签就是「**随时能清、清了不出事**」——不是每期清，而是想清的时候整个删掉，不会牵连重要文件。

| 放这里 | 不放这里 |
|---|---|
| 提音量副本、SRT、words.json、剪辑脚本 | 素材原目录（那是人的地盘） |
| 探针片、中间片段 | 系统临时目录（会被清掉，找不到） |

**成片**放回人习惯取用的地方。

## 常见问题

**Q: 可以用别的 ASR 吗？**
可以，只要它给**逐字时间戳**。给不了的话（比如 SenseVoice 只有句级），本项目的剪点吸附就用不了，只能退化成纯转录。

**Q: 一定要 GPU 吗？**
不一定。`Qwen3-ASR-0.6B` 在 CPU 上能跑，只是慢。见 `docs/models.md`。

**Q: 剪切为什么不自动做？**
因为剪点判断有主观成分，而内容删减权必须在人手里。见 `docs/rules.md`。
