# oral-cut · 本地口播剪辑

> 把一段口播视频丢进去，出**剪辑清单**——不是自动剪，是**告诉你该剪哪儿，你点头才剪**。

**转录和剪辑执行全部在你本地完成** —— 不调用任何云端 ASR API，视频素材不上传。

不过要说准确一点：如果你是通过**云端 Agent**（Claude Code / Codex / 各类在线助手）调用它，**Agent 自身的模型推理仍可能产生费用**，发给它的文本（逐字稿、剪辑清单）也要遵循对应服务的隐私政策。想真正全程离线，就用本地 Agent，或直接跑命令行。

---

## 它解决什么问题

录口播的人都有一个共同动作：**听回放，找废 take、找口吃、找长静音**，手动拖时间轴。

这一步占掉剪辑一半的时间，而且纯机械。

这个工具做的是：**把机械的活算出来，把内容的决定权留给你。**

它不会自作主张剪掉你说的一句话。它会给你一张清单：

```
0:12.4 → 0:14.1  ｜「那个那个，我重新说」  ｜ 重录标记，前一遍作废
1:03.8 → 1:05.2  ｜ （静音 1.4 秒）        ｜ 超过阈值，可剪
2:47.0 → 2:47.6  ｜ （静音 0.6 秒）        ｜ 说话换气，保留
```

你划掉不想剪的，说一声，它才动手。

## 三条规则（这个项目真正的资产）

大多数"转录工具"止步于转文字。真正难的是**怎么决定剪哪儿**——下面是踩出来的：

### 1. 剪点必须吸附到**字级时间戳**，不能信静音检测的边界

`ffmpeg silencedetect` 报的"静音区间"，边界经常落在字上。照它剪，会把尾音切掉半个字。

**做法**：拿逐字时间戳，把每个剪点的起止点收缩到不与任何字相交——起点往后移到该字的 `end`，终点往前移到该字的 `start`。

### 2. 静音线是 **0.9 秒**，且要用电平交叉验证

- ≤ 0.9 秒 → 保留。那是说话的呼吸，剪了听着像被掐断。
- \> 0.9 秒 → 可剪。

但**先用字级间隙筛，再用电平验证**——低电平素材上单靠 dB 阈值会把轻读的字判成静音。间隙够长但电平不低 = 识别漏掉的话，**不剪，报给人**。

### 3. 内容删减权在**人**，不在 AI

| 归 AI（授权即可动手） | 归人（只报告，不动手） |
|---|---|
| 片头／片尾静音 | 删掉一句**有含义的话** |
| 废 take、说错重来 | 删掉一个论点、一个例子 |
| 静音 > 阈值 | 任何「以少为多」的取舍 |

**判断信号**：要说删的那句，如果删掉之后**意思会变**——它是内容，不是剪点。

> 配套血案：AI 曾把「我决定删掉那段」当成机械剪点，直接重渲了一版，还覆盖了用户正在剪映里编辑的文件。半天的活儿没了。
>
> 所以还有第零条铁律：**成片只增不改**。已交付的文件视为只读，改版一律出新文件名（`-cut-v2`）。

## 安装

> ⛔ **不要把单个 `SKILL.md` 复制进技能目录就算了。**
>
> 本技能依赖同仓库的配套文件才能运行：`scripts/`（环境引导、模型下载、转录、剪点计算、剪切）、`requirements.txt`、`batch_transcriber.py`（转录引擎）、`docs/`。
> 只装一个 Markdown 文件，Agent 知道该干什么，但**没有工具可调**。

### 第 1 步 · 整仓克隆到固定位置

```bash
git clone https://github.com/992939504/oral-cut.git ~/oral-cut
```

位置随你，下文一律用 `$ROOT` 指代**仓库根目录**（= `SKILL.md` 所在目录）。

**判定标准**：`ls "$ROOT"` 应该能看到 `SKILL.md`、`scripts/`、`batch_transcriber.py`。看不到就是路径错了。

### 第 2 步 · 交给 AI agent（Hermes / Claude Code / Codex 等）

把**整个仓库目录**放进技能目录，**不是只拷 SKILL.md**：

```bash
# 例：Hermes profile 的技能目录（换成你自己的）
git clone https://github.com/992939504/oral-cut.git \
  ~/.hermes/profiles/<profile>/skills/oral-cut
```

### 第 3 步 · 一键装环境

```bash
bash "$ROOT/scripts/setup.sh"
```

依次：**检测环境 → 建独立虚拟环境 → 装依赖 → 探测你的机器 → 推荐最合适的模型 → 你确认后从 ModelScope 下载**。

每一处需要你点头的地方都会停下来等。**不会默默装任何东西。**

### 手动跑

```bash
ROOT=~/oral-cut        # ← 改成你克隆到的位置
cd "$ROOT"

# 1. 建虚拟环境（一定用独立的，别装进系统 Python）
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2. 下载模型（会先列清单让你确认体积和路径）
.venv/bin/python scripts/setup_models.py

# 3. 转录
bash scripts/transcribe.sh 你的视频.mp4

# 4. 出剪辑清单（只算，不剪）
.venv/bin/python scripts/plan_cut.py 你的视频.words.json --media 你的视频.mp4 --repeats
```

需要 `ffmpeg` 在 PATH。

> **先 `cd "$ROOT"`，再跑上面这些相对路径。** 不要依赖"当前工作目录正好对"。
> 仓库里的脚本自己会用绝对路径定位同目录的文件（`setup.sh` / `transcribe.sh` 都基于自身位置反推），但文档里的相对路径是相对**仓库根**的。

### 字幕呢？

**默认不做字幕，只做剪辑。**

转录出来的 SRT 是内部工具（用来定位剪点），不是成品字幕。要成片字幕的话，问一声就行——见 SKILL.md 的「字幕是可选项」。

## 模型选择

| 你的机器 | 推荐 | 下载体积 |
|---|---|---|
| 有 NVIDIA 显卡（8G+ 显存） | Qwen3-ASR-1.7B + ForcedAligner | 约 6 GB |
| 显存小 / 只想跑 CPU | **Qwen3-ASR-0.6B** + ForcedAligner | 约 3 GB |
| 极端低配（树莓派级） | sherpa-onnx + Paraformer | 约 300 MB |

详见 [`docs/models.md`](docs/models.md)。

> **为什么 CPU 档推荐 0.6B 而不是更快的 SenseVoice？**
> 因为整套剪辑规则依赖**逐字时间戳**。SenseVoice 很快，但只给句级时间戳——剪点吸附就没法做了。0.6B 慢一点，但同一条管线、同样的字级精度。

---

## 它不做什么

- **默认不生成成品字幕**。它出的 SRT 是内部稿，用来定位剪点。要不要字幕由你定，成品字幕交给你惯用的剪辑软件。
- **不自动剪**。它出清单，你点头才剪。
- **不做包装**。没有花字、转场、B-roll、动效。（包装层是另一个项目）
